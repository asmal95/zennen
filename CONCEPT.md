# Концепция: ИИ-Диктофон + Дневник с пайплайном истории

## 1. Проблема и идея

Люди думают вслух в течение дня, но мысли теряются: голосовые себе, заметки в 5 местах, планы в голове. Идея — **один вход (Telegram) и умный пайплайн**, который превращает поток в структуру.

Принцип: **«Ты просто говоришь, бот всё раскладывает и помнит».**

> Уточнение концепции (voice-first агент): основной ввод — **голосовые**, но **текст равноправен**
> (писать мыслями так же нормально, как говорить — рубить с плеча не будем).
> Пользователь каждый день излагает мысли в чат, система **автоматически ведёт журнал без участия пользователя**:
> список заметок, сущности, планы, напоминания. Никаких форм, настроек и «заполни поля».
> Это похоже на обычного чат-агента, но с одним отличием: **инициатива ввода всегда у человека
> (голосом или текстом), инициатива структурирования — всегда у системы**.
> Пользователь не командует агентом, он просто думает вслух / пишет поток.

## 2. Пользовательский цикл

1. **Запись (0 сек трения):** голосовое / текст / пересланное / фото с подписью — всё принимается.
2. **Мгновенный ответ:** расшифровка + «Разложил так: 📌 Планы: …, 💡 Идеи: …, ✅ Задачи: …».
3. **Хранение по дням:** каждая запись привязана к дате, день собирается как лента.
4. **Просмотр:** `/today`, календарь, аспекты, поиск.
5. **Напоминания:** бот сам возвращает: «Ты хотел позвонить маме — сделал?», утренний план, вечерняя рефлексия.
6. **Рефлексия:** недельный дайджест: что планировал / что сделал / о чём думал / как менялось состояние.

## 2.1. Автоведение: заметки, сущности, планы, напоминания

**Заметка (Note)** = одна расшифровка одного голосового + её блоки. Лента заметок — это «сырая история дня».
Пользователь ничего не сохраняет явно: каждая голосовая автоматически становится заметкой с датой/временем.
Дата записи — это дата *событий*, не дата отправки: LLM в том же вызове возвращает `entry_date`
(«вчера», «позавчера», день недели по таблице дат, явная дата); упоминание срока задачи на неё не влияет.
Одна запись — одна дата (смешанные «вчера X, сегодня Y» относятся к доминирующей). Бот подтверждает:
«📅 Записал за 2026-10-02», если это не сегодня.

**Сущности (Entities)** выделяются автоматически из каждого голосового:
- `person`: люди (@Маша, «созвон с Иваном», «мама»)
- `project`: проекты/теги (#стартап, «лендинг», «диплом»)
- `place`: места («офис», «дача», «Стамбул»)
- `date`: даты/сроки («завтра», «в понедельник», «к 10-му»)
- `money`: суммы («5000 руб», «долг 20к»)
- `promise`: обещания («обещал позвонить», «договорились что…»)

Сущности — это клей между днями: по ним строятся `/person`, `/project`, «всё про отпуск».

**Планы vs Задачи vs Напоминания** — важно различать:
- `plan` — намерение («хочу разобрать гараж»); с датой-целью («завтра хочу в бассейн», «в пятницу встреча») → таблица `plans` с `target_day`, всплывает утром этого дня и в `/plans`. Будущие события-`fact` («в пятницу встреча») тоже становятся планами, иначе «я же говорил» потеряется.
- `task` — действие + срок/ответственный («завтра сдать отчёт») → попадает в `/tasks`, требует закрытия.
- `reminder` — задача со временем срабатывания («напомни в 9 утра позвонить») → ставит триггер в планировщик.
  Типы напоминаний: `deadline` (к сроку), `follow-up` («проверить, сделал ли?» вечером), `routine` (ежедневное «таблетка», «спорт»).

Правило: система сама решает, что из голосового стало планом/задачей/напоминанием, и коротко сообщает:
«📌 в планы, ✅ в задачи (#12), ⏰ напомню завтра в 9:00». Пользователь только подтверждает голосом «да/нет/исправь».

## 3. Таксономия аспектов (ядро структурирования)

Каждая запись разбивается на блоки с одним аспектом:

| Аспект | Эмодзи | Что попадает | Пример |
|---|---|---|---|
| `fact` — Факты / Хроника | 🕒 | что произошло | «Созвон с Иваном в 11:00» |
| `thought` — Мысли / Рефлексия | 💭 | рассуждения, сомнения | «Кажется, я выгораю из-за…» |
| `plan` — Планы / Намерения | 📌 | без жёсткой даты | «Хочу на выходных разобрать гараж» |
| `task` — Задачи | ✅ | с датой/действием | «Завтра в 10:00 сдать отчёт» |
| `idea` — Идеи / Инсайты | 💡 | озарения, гипотезы | «А что если делать доставку через…» |
| `emotion` — Состояние | ❤️ | эмоции, энергия 1–10 | «Тревожно, энергия 4/10» |
| `health` — Здоровье | 🏃 | сон, спорт, еда, симптомы | «Спал 5 часов, болит голова» |
| `work` — Работа / Проекты | 💼 | по проектам с тегами | «#стартап: допилил лендинг» |
| `people` — Люди | 👥 | упоминания людей | «@Маша помогла с…» |
| `money` — Финансы | 💰 | траты, доходы | «Потратил 5000 на…» |
| `gratitude` — Благодарности | 🙏 | позитив | «Спасибо дню за…» |
| `decision` — Решения | ⚖️ | выбор, вывод | «Решил отказаться от…» |
| `other` — Прочее | 📝 | всё остальное | — |

Зачем фиксированная таксономия: по ней строятся все вьюхи (`/tasks` = `task`, `/ideas` = `idea`, недельный отчёт группирует по аспектам), поиск и аналитика.

Дополнительно каждый блок имеет: `tags` (#проект), `mentions` (@человек), `due` (дата задачи), `energy` (1–10, если есть).

## 4. Пайплайн истории (архитектура данных)

```
Stage 0  INPUT      voice.ogg / text / photo
           ↓
Stage 1  TRANSCRIBE Whisper → transcript + duration
           ↓
Stage 2  ENTRY      entries(user_id, date, transcript, type) — сырьё, неизменяемое
           ↓
Stage 3  ANALYZE    LLM API → JSON blocks[{aspect, content, tags, due, energy}] (только LLM, без эвристик;
           при ошибке LLM разбор пропускается, сырьё в entries сохраняется)
Stage 4  LINK       извлечь #теги, @людей, даты («завтра», «в понедельник»)
           ↓
Stage 5  ACTIONS    tasks ← blocks[task/plan с датой]; reminders.schedule()
           ↓
Stage 6  AGGREGATE  daily_digest, weekly_review, mood_graph — по расписанию / команде
           ↓
Stage 7  RECALL     /search (FTS сейчас, embeddings в V2), напоминания, «год назад»
```

Ключевое свойство: **сырьё никогда не перезаписывается**. Переразбор можно запускать заново (смена промпта → `re-analyze`), история сохраняется.

Схема MVP (SQLite):
- `entries(id, user_id, day, kind, raw_text, transcript, created_at)` — заметки
- `blocks(id, entry_id, user_id, day, aspect, content)` — разбор по аспектам
- `entities(entry_id, user_id, day, type, value)` — люди/проекты/места/даты/суммы (новое)
- `tasks(id, user_id, entry_id, text, due, done, created_at)` — задачи/планы со сроком
- `reminders(id, task_id, user_id, fire_at, kind, sent)` — триггеры напоминаний (новое)
- `delegations(id, user_id, entry_id, title, context, status, agent)` — карточки делегирования (новое, см. §9)

V2: Postgres + pgvector (`embeddings`), таблицы `days`, `people`, `projects`.

## 4.1. Делегирование внешнему агенту — только через плагин (не в этом проекте)

Принцип разделения: **этот проект — память и структура, а не исполнитель**.
Ядро (диктофон-дневник) никогда само не бронирует билеты, не пишет код, не ходит в интернет.
Если из голосового следует «надо реально сделать» (найти, забронировать, написать, посчитать) —
ядро готовит **DelegationCard** и отдаёт её наружу:

```json
{
  "title": "Найти зал для созвона на 10 человек",
  "context": "Из голосового 2026-09-28 + связанные блоки #стартап, @Иван",
  "due": "2026-09-30",
  "entities": {"people": ["Иван"], "project": ["стартап"]},
  "source_entry_ids": [42, 43]
}
```

Интерфейс плагина (см. `internal/services/delegate.go`):

```go
type AgentPlugin interface {
    Name() string // "calendar", "coder", "travel"...
    CanHandle(ctx context.Context, card DelegationCard) bool
    Handle(ctx context.Context, card DelegationCard) string // возвращает report-строку
}
```

Правила:
1. Делегирование — **только с явного голосового согласия** («да, поручи», «отдай агенту»).
   Авто-делегирование запрещено: ядро предлагает («Могу отдать агенту-календарю. Поручить?»), человек подтверждает голосом.
2. В MVP плагины — заглушки (`NoOpPlugin` / `CalendarPlugin`): сохраняют карточку со статусом `proposed/approved/done`,
   но ничего внешнего не делают. Реальные агенты подключаются позже без изменения ядра.
3. Каждое делегирование связано с исходными `entry_id` — всегда можно посмотреть «откуда это взялось».
4. Команды: `/delegations` — список карточек, голосом «поручи … агенту» — создать.

Примеры будущих плагинов (вне скоупа ядра): календарь (создать встречу), кодер (завести issue), тревел (найти билеты),
писатель (собрать текст из заметок недели), «напоминалка+» (позвонить/написать за тебя).

## 5. Сценарии использования

**Утро:** «Сегодня надо сдать отчёт, созвон в 11, тревожно» → `task: сдать отчёт`, `fact: созвон 11:00`, `emotion: тревожно` → в 9:00 бот присылает план дня.

**День:** 5 голосовых вразнобой → все падают в ленту сегодня, бот коротко подтверждает каждое.

**Вечер:** бот в 21:00: «Что было главным сегодня? + у тебя 2 незакрытые задачи». Отвечаешь голосом → рефлексия.

**Неделя:** `/week` → «Планировал 12, выполнил 8. Топ-темы: #стартап, @Иван. Энергия: пн 4 → пт 7. Открытые идеи: …».

**Поиск:** «Что я думал про отпуск в марте?» → `/search отпуск` → блоки + даты.

**Напоминания:** «Напомни завтра позвонить маме» → `task(due=завтра)` → утром напоминание + вечером «сделал?».

## 6. Что дополняет концепцию (предложения)

1. **Умные вопросы:** если запись только «всё плохо», бот задаёт 1 уточняющий вопрос (техника CBT/коучинга), а не молчит.
2. **Шкала состояния:** раз в день просит энергию 1–10 одной кнопкой → график настроения в `/week`.
3. **Связи:** `@люди` и `#проекты` становятся отдельными вьюхами: `/person Маша` — всё про неё.
4. **«Год назад» / «Месяц назад»:** воспоминания для длинной мотивации.
5. **Экспорт:** `/export` → Markdown-дневник по месяцам (для Obsidian/Notion).
6. **Приватность:** локальный режим (Whisper tiny + локальная LLM), шифрование; удаление уже есть: кнопки 🗑 под разбором (с подтверждением) и `/delete_day [ГГГГ-ММ-ДД]`, каскад чистит разбор/открытые задачи/несработавшие напоминания, выполненные задачи не трогаем как историю. Честная оговорка: копии живут в `data/backups/` до 14-дневной ротации.
7. **Мультимодальность:** фото чека → `money`, скрин → `idea`, кружок → transcribe.
8. **Голосовые ответы:** дайджест голосом (TTS) для «диктофонности».
9. **Семья/команда:** общий дневник проекта (опционально, V3).
10. **Анти-спам:** группировка подтверждений — если 3 голосовых за 2 минуты, один ответ-итог.

## 7. UX-правила

- Подтверждение ≤ 10 сек, короткое (3–6 строк), с кнопками «Исправить / Удалить / В задачу».
- Никогда не терять сырьё: даже если LLM упал — сохранить транскрипт.
- Команды минимум: главное — просто говорить, команды только для просмотра.
- Русский язык по умолчанию; часовой пояс персональный: `TZ` в `.env` — только дефолт, при `/start` бот спрашивает зону кнопками (или `/tz Asia/Almaty`), утро/вечер/напоминания/границы дней — по ней.

## 8. Метрики успеха

- Записей/день ≥ 2, голосовых ≥ 50%
- % записей с извлечёнными задачами/планами
- Возврат на следующий день (retention D1/D7)
- Закрытие задач из бота
- Запросы `/week` и `/search` (значит историей пользуются)
