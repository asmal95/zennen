# WEB-UI: дизайн веб-вьювера дневника

Статус: **реализовано и запущено** на https://nen.zenai.space (systemd `diaryweb`, nginx + Let's Encrypt). Цель: открыть ссылку из бота на телефоне
и удобно читать свою историю. Только чтение в v1 — никаких действий, минимум
авторизации, ноль LLM-затрат на просмотр, ноль новых СУБД.

## 1. Принципы

1. **Бот — вход, веб — витрина.** Вся логика (разбор, задачи, напоминания) остаётся в боте. Веб только рендерит то, что уже лежит в SQLite.
2. **Read-only v1.** Нет действий → нет CSRF, нет форм, нет состояния на сервере кроме сессии. Действия (закрыть задачу, энергия, удаление) — v2 отдельным решением.
3. **Телефон прежде всего.** Одна колонка, крупные дни, тёмная тема в стиле Telegram. Десктоп — тот же layout по центру, без отдельной вёрстки.
4. **Ноль LLM-цены на просмотр.** Все страницы строятся SQL-запросами по готовым `blocks`/`entities`/`tasks`/`energy`. Единственное исключение — weekly review: генерируется по запросу и **кэшируется** (таблица `week_cache` или файл), повторный показ бесплатный.

## 2. Архитектура

```
Telegram-бот (пишет) ──┐
                       ▼
              diary.db (SQLite, один файл)
                       ▲
Веб-вьювер (только читает, open read-only) ── Caddy :443 ── интернет ── телефон
```

- **Тот же Go-модуль**, новый пакет `internal/web/` + точка входа `cmd/web/main.go`. Переиспользуются `internal/db` (Store + новые read-методы) и `internal/services` (RenderDay-подобные форматтеры; HTML-шаблоны отдельно).
- **Стек рендера:** stdlib `net/http` + `html/template` (автоэкранирование!), минимум vanilla CSS, без JS-фреймворков.
- **Два файла, честное разделение записи:** `diary.db` веб открывает **read-only** (`mode=ro`) — повредить дневник не может; все записи веба (сессии, кэш ревью) идут в отдельный `data/sessions.db` (SESS_DB_PATH), который бэкапить не нужно (потеря = перевыпуск `/link` + регенерация кэша). Кратковременные локи SQLite при записи бота для читателя прозрачны.
- **Отдельный systemd-юнит** `diaryweb.service`, слушает только `127.0.0.1:8080`. Наружу — только через Caddy.

## 3. Страницы v1 (все read-only)

| Путь | Что показывает | Источник данных |
|---|---|---|
| `/` | Лента последних 14 дней: записи с блоками по аспектам, энергия дня, открытые задачи дня | `entries` + `blocks` + `energy` + `tasks` |
| `/day?d=ГГГГ-ММ-ДД` | Один день + кнопки ←/→ (навигация-календарь) | `DayBlocks`, `WeekEnergy`-аналог на день |
| `/week` | Статистика + кэшированный нарративный итог (кнопка «перегенерировать») | `WeekBlocks`, `week_cache` |
| `/tasks` | Открытые + закрытые за 30 дней | `OpenTasks`, `DoneTasksSince` |
| `/ideas` | Банк идей | `BlocksByAspect(idea)` |
| `/person?name=`, `/project?tag=` | История по сущности | `EntityHistory` (уже есть!) |
| `/search?q=` | Поиск (сейчас LIKE; позже FTS5 — см. ROADMAP) | `SearchBlocks` |
| `/export?month=` | Скачать Markdown | `RenderExportMarkdown` (уже есть!) |

Почти всё — готовые методы Store и сервисов, веб лишь оборачивает их в HTML. Это главный аргумент за такой дизайн: ~70% бэкенда уже написано.

## 4. Авторизация: magic link из бота

Без паролей и без Telegram Login Widget (ему нужен домен в BotFather-настройках и сложнее UX):

1. В боте команда `/link` → генерируем токен (`crypto/rand`, 32 байта, hex), храним **только его SHA-256** в таблице `web_sessions(token_hash, user_id, created_at, expires_at)` (файл `data/sessions.db`, отдельно от дневника), отдаём URL `https://domain/r/<токен>`. Превью ссылки в сообщении **выключено** (`LinkPreviewOptions.is_disabled`).
2. Заход по `/r/<токен>` (GET): только **проверяем** токен и показываем кнопку «Войти». Гашения тут нет — GET шлют и краулеры превью Telegram, которые так уже съели одну ссылку (401 сразу после выдачи, поймано в проде).
3. Кнопка → POST `/r/consume`: сверяем, гасим (одноразовый), ставим `Secure; HttpOnly` cookie сессии на 30 дней, редирект на `/`. Краулеры POST не ходят.
4. Дальше — проверка cookie → `user_id` → все запросы scoped только его данными (тот же принцип владения, что `EntryDay` в боте).
5. Отзыв: команда `/revoke` в боте чистит сессии пользователя. Rate-limit на `/link` (не чаще 1 раза в минуту) против спама токенами.
6. Наблюдаемость: access-лог (method/path/status, токены и query режутся: `/r/…`, `?…) — по нему видно сценарий «GET 200 → POST 302 → GET 401» и отличать stale-тапы от багов. Истёкшая ссылка — отдельная страница `expired.html` с объяснением и советом открыть ссылку в обычном браузере (встроенный просмотрщик Telegram иногда теряет cookie).

## 5. Хостинг и TLS (факт)

- **nginx** (уже стоял): `server nen.zenai.space` → `proxy_pass 127.0.0.1:8070`, серт Let's Encrypt через certbot (`/etc/nginx/sites-enabled/nen.zenai.space`). Caddy не понадобился.
- `diaryweb.service`: `Restart=always`, enabled, `WorkingDirectory` = корень проекта. Логи — journald, как у бота. Проверка: `curl https://nen.zenai.space/` → 302 на `/login`.

## 6. Безопасность (чеклист v1)

- [ ] Слушать только localhost; наружу — только Caddy с TLS (HSTS включить).
- [ ] БД открыта read-only; cookie `Secure + HttpOnly + SameSite=Lax`, 30 дней.
- [ ] Токены `/r/`: 256 бит энтропии, хранится SHA-256, одноразовые, TTL 15 минут, `/revoke` в боте.
- [ ] Все данные только своего `user_id` (scope из сессии, не из query).
- [ ] `html/template` по умолчанию экранирует — сырые строки в шаблоны не таскать.
- [ ] Security headers от Caddy (X-Content-Type-Options, frame-ancestors).
- [ ] Rate-limit `/r/*` и `/link` на уровне Caddy/кода.

## 7. Фазы

- **v1 (этот дизайн):** чтение — лента, день, неделя (+кэш ревью), задачи, идеи, person/project, поиск, export-скачивание, `/link` + `/revoke`.
- **v2 (отдельное решение):** действия — закрыть задачу, энергия tap, удаление с подтверждением, перегенерация ревью. Потребует CSRF-токены и POST-формы; авторизация та же.
- **Не делаем:** регистрация/логин по паролю, публичные ссылки «поделиться днём», realtime-обновления (polling/websockets), отдельный фронтенд-билд.

## 8. Оценка

~400–500 строк Go + шаблоны: `internal/web/{server,handlers,templates}.go`, `cmd/web/main.go`, миграция `web_sessions` (+ позже `week_cache`), 2 команды в боте (`/link`, `/revoke`), Caddyfile, `diaryweb.service`, доки. LLM-затрат на просмотр — ноль (ревью только по кнопке, с кэшем).
