# ИИ-Диктофон Дневника в Telegram (Go)

Личный голосовой дневник с «пайплайном истории»: в течение дня кидаешь боту голосовые или текст — он транскрибирует, раскладывает мысли по аспектам, хранит по дням, вытаскивает планы/задачи/идеи, напоминает о договорённостях и собирает недельные итоги. Принцип: **ты просто говоришь — бот всё раскладывает и помнит**.

Голос — основной способ ввода, текст равноправен. Исполнения задач в ядре нет: бот — это память и структура, внешние агенты-исполнители подключаются позже отдельными плагинами.

## Возможности

- **Запись**: голосовые, аудио, кружки, текст; расшифровка через Whisper
- **Разбор**: 13 аспектов (факты, мысли, планы, задачи, идеи, состояние, здоровье, работа, люди, деньги, благодарности, решения) — только LLM, без эвристик
- **Даты**: запись относится к дате *событий* — «вчера», «позавчера», дни недели и явные даты определяются автоматически; сроки задач («завтра сдать») на это не влияют
- **Сущности**: люди, проекты, места, даты, суммы, обещания — клей между днями
- **Напоминания**: «напомни через час / в 15:30 / завтра» + утренний план (9:00) и вечерняя рефлексия (21:00)
- **История**: дни, недели с нарративным итогом от LLM, лента заметок, поиск, «всё про человека/проект», энергия дня 1–10 с графиком
- **Управление**: кнопки под разбором (в задачу / исправить / удалить), удаление дня, экспорт месяца в Markdown для Obsidian/Notion

## Команды

| Команда | Что делает |
|---|---|
| `/today`, `/day [ГГГГ-ММ-ДД]` | день (по умолчанию сегодня) |
| `/notes` | последние заметки |
| `/week` | 7 дней: статистика + итоги недели от LLM |
| `/tasks`, `/done <id>` | открытые задачи, закрыть |
| `/ideas` | банк идей |
| `/energy [1–10]` | энергия дня (без аргумента — кнопки) |
| `/person <имя>`, `/project <тег>` | всё про человека / проект |
| `/delegations` | карточки для внешнего агента |
| `/search <запрос>` | поиск по дневнику |
| `/export [ГГГГ-ММ]` | Markdown за месяц файлом |
| `/delete_day [ГГГГ-ММ-ДД]` | удалить день |

## Быстрый старт

```bash
cp .env.example .env   # вписать BOT_TOKEN и OPENAI_API_KEY (оба обязательны)
go run ./cmd/bot
# или: go build -o diarybot ./cmd/bot && ./diarybot
# или: docker compose up --build
```

Конфиг (`.env`): `BOT_TOKEN`, `OPENAI_API_KEY`, `OPENAI_BASE_URL` (дефолт — OpenRouter `https://openrouter.ai/api/v1`, слаги с префиксом: `openai/gpt-4o-mini`, `openai/whisper-large-v3-turbo`), `OPENAI_MODEL`, `OPENAI_STT_MODEL`, `TZ`, `DB_PATH`, `MORNING_HOUR`, `EVENING_HOUR`. Для прямого OpenAI поменяй BaseURL на `https://api.openai.com/v1` и слаги на `gpt-4o-mini` / `whisper-1`.

Прод: systemd-юнит `diarybot` (`Restart=always`, enabled) — `systemctl restart diarybot`, логи `journalctl -u diarybot`. Бэкапы SQLite — автоматически каждый день в 3:00 в `data/backups/` (ротация 14 дней).

## Приватность

Удаление — hard delete с каскадом (разборы, открытые задачи, несработавшие напоминания). Выполненные задачи сохраняются как история. Честная оговорка: копии удалённого живут в бэкапах до 14-дневной ротации. `.env` и `data/` никогда не коммитятся (см. `.gitignore`).

## Документы и структура

- `CONCEPT.md` — концепция, таксономия, пайплайн, сценарии
- `ROADMAP.md` — план по фазам (что сделано / что дальше)
- `AGENTS.md` — инструкция для AI-агента, работающего с кодом
- `archive/python-bot/` — первый прототип на Python (история, не запускается)

```
cmd/bot/            # точка входа: polling + планировщик
internal/
  config/           # конфиг из .env
  db/               # SQLite: entries/blocks/entities/tasks/reminders/delegations/energy
  services/         # stt, analyze (LLM), entities, remind, pipeline, review,
                    # people, energy, delegate, render, export, llm (клиент)
  handlers/         # приём сообщений, команды, кнопки, колбэки
  scheduler/        # утро/вечер, ежеминутные напоминания, бэкап
```

Пайплайн: `[voice/text] → transcribe → entry → analyze(аспекты+дата) → entities → tasks/reminders → DelegationCard(proposed) → digest`. Сырьё (`entries`) пишется один раз и никогда не правится кодом — только явным исправлением или удалением пользователя.
